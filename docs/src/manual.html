8.1 Хэрэглэгчийн заавар

8.1.1 Програмын зорилго

Linux kernel-ийн дугуй хоёр холбоост жагсаалт struct list_head-ийг турших, үйлдэл бүрийн дараа next/prev заагч, kmalloc/kfree хэрхэн өөрчлөгдөхийг граф дээр харах. Дөрвөн бүтэц: Өнгөний жагсаалт (номын Part I), Collatz (Part II), Стек, Дараалал. Граф нь хуурамч загвар биш, C хөдөлгүүрийн бодит заагчаас зурагдана.

8.1.2 Дэмжих орчин

  • OS: Linux (Arch Linux, Linux 7.2.11 дээр туршсан). Тестийн нэг хэсэг Linux-ийн /proc ашигладаг тул macOS/Windows-д туршаагүй.
  • Хэрэгсэл: gcc (16.2.1-ээр туршсан), make (GNU Make 4.4.1), python3 (3.14.8; зөвхөн стандарт сан).
  • Browser: JavaScript ба SVG дэмждэг орчин үеийн browser (Brave 156/Chromium дээр туршсан). Интернет холболт шаардахгүй.

8.1.3 Суулгах, нээх алхам

  1. Repository-г татах: git clone <GitHub холбоос> kernel-data-structures && cd kernel-data-structures (холбоос байхгүй бол хүргэсэн хавтсыг хуулж cd хийнэ — 8.2.1)
  2. Бүтээх: make — build/kds_engine үүснэ.
  3. (Заавал биш) Шалгах: make test — эцэст нь All available tests passed. гарна.
  4. Асаах: make run — терминалд http://127.0.0.1:8080 гарна.
  5. Browser-ээр энэ хаягийг нээнэ. Дээд талд «Хөдөлгүүр холбогдсон» гэж харагдвал бэлэн.

8.1.5 Ажиллуулах, зогсоох, reset хийх

  • Ажиллуулах: make run. Үйлдэл хийхэд «Үйлдлийг гүйцэтгэх» (эсвэл Enter).
  • Зогсоох: make run-ийн терминал дээр Ctrl+C. Хөдөлгүүр дуусахдаа чөлөөлөөгүй санах ой үлдсэн бол LEAK: live=N гэж бичнэ (хэвийн үед гарахгүй).
  • Reset: «Бүх бүтцийг хоослох» товч (reset) — 4 бүтцийг чөлөөлж, алдааны тарилгыг унтраана; kmalloc/kfree хуримтлагдсан тоолуур үргэлжилнэ. Хөдөлгүүрийг бүрэн дахин эхлүүлэх: сервер зогсоож дахин асаана, эсвэл curl -X POST http://127.0.0.1:8080/api/restart.
  • Түүх: «Үйлдлийн түүх» дэх ← → товч, гулсуур, «Сүүлийн алхам». Өнгөрсөн алхам зөвхөн уншигдана (үйлдэл түгжигдэнэ). Түүх нь browser-ийн табд хадгалагдах бөгөөд хуудсыг дахин ачаалбал алга болно; бүтцүүд хөдөлгүүрт хэвээр үлдэнэ. Анхаар: ?run=…-тай хуудсыг дахин ачаалбал командууд дахин ажиллана.

8.1.7 Жишээнүүд

Жишээ 1 — Номын Part I: 4 өнгө, хайх, устгах

  1. Өнгөний жагсаалт таб → «Номын 4 өнгө». Хүлээгдэх үр дүн: 4 зангилаа; dmesg-д 
    color[0]: red=138, green=43, blue=226
color[1]: red=255, green=0, blue=0
color[2]: red=0, green=255, blue=0
color[3]: red=0, green=0, blue=255
    Санах ой (дөнгөж асаасан хөдөлгүүр дээр): kmalloc 4, kfree 0, амьд 4, 128 байт. Эхний зангилаа нь violet (138, 43, 226).
  2. «Өнгөөр хайх», red = 255 → «Олдсон» тодорно: #2 (индекс 1). Хайлтын зам #1 → #2 ... анимацитай.
  3. «Индексээр устгах», index = 1 → list_del(&#2->list), kfree(#2); граф #1 → #3 → #4 болно. Тоолуур: kmalloc 4 / kfree 1 / амьд 3 / 96 байт.
  4. «Бүх бүтцийг хоослох» → амьд 0.

Жишээ 2 — Part II: Collatz дараалал, хайх, алдаа

  1. Collatz таб → «Дараалал үүсгэх», start = 27. Хүлээгдэх: 112 зангилаа, 111 алхам, оргил 9232; 27 → 82 → 41 → 124 → 62 → 31 → …; Амьд зангилаа 112 (24 B × 112 = 2,688 байт).
  2. «Утгаар хайх», value = 9232 → хайлт эхнээс явж 77-р индексэд (оргил) олдоно.
  3. Алдааны шалгалт. «Командыг шууд оруулах» хэсэгт collatz run start=0 гэж бичиж илгээнэ (энэ нь форм биш: «Дараалал үүсгэх» формын start талбар min=1 тул browser 0-г өөрөө хаадаг бөгөөд engine хүртэл хүрэхгүй). Улаан мөр E_RANGE; граф (112 зангилаа) болон тоолуур өөрчлөгдөхгүй.
  4. «Утгаар устгах», value = 9232 → 111 зангилаа.
  5. «Дараалал үүсгэх», start = 837799 → 525 зангилаа, оргил 2974984576 (int32-ээс их, тиймээс 64 бит).

Жишээ 3 — Стек (LIFO) ба дараалал (FIFO)

Стек: push 10, push 42, push −2 → TOP = −2; pop → −2 гарна, TOP = 42. Дараалал: enqueue 10, enqueue 42 → FRONT = 10, REAR = 42; dequeue → 10 гарна.

Жишээ 4 — Командыг URL-ээр ажиллуулах

http://127.0.0.1:8080/?run=reset;color%20example;color%20delete%20index=1 — reset хийгээд номын жишээг үүсгэж, 1-р индексийг устгана.

Жишээ 5 — ENOMEM тарилга

«Командыг шууд оруулах» хэсэгт inject_fail after=2, дараа нь color add_tail red=1 green=2 blue=3-ийг гурав гүйцэтгэнэ. Эхний хоёр амжилттай, гурав дахь нь E_NOMEM («kmalloc failed; the previous state is preserved») — граф өөрчлөгдөхгүй. inject_fail off — унтраана.

8.2.7 Жинхэнэ kernel module (заавар; энд ажиллуулаагүй)

Анхааруулга. Kernel module дээр алдаа гарвал систем гацаж болно. Зөвхөн виртуал машин дээр туршина. Энэ хэсгийн командуудыг тайланг бэлтгэх орчинд (kernel header байхгүй) ажиллуулаагүй; доорх үр дүн нь бодитоор баталгаажаагүй, зөвхөн кодоос хүлээгдэж буй зүйл.
make module KDIR=/lib/modules/$(uname -r)/build      # src/kernel/color_list.ko, collatz.ko
sudo insmod src/kernel/color_list.ko && dmesg | tail -n 4  # Part I
sudo rmmod color_list
sudo insmod src/kernel/collatz.ko start=15 && dmesg | tail -n 18   # Part II (start орхивол 25)
sudo rmmod collatz

Хүлээгдэх dmesg (формат нь shim дээр тест-ээр баталгаажсан): Part I — color[0]: red=138, green=43, blue=226 … color[3]: red=0, green=0, blue=255; Part II, start=15 — collatz[0]: value=15 … collatz[17]: value=1 (18 мөр). start=0 үед init -EINVAL буцааж insmod алдаатай дуусах ба dmesg-д collatz: start must be positive гарна.

8.2.9 Known issues

  • Жинхэнэ .ko-ийг энд бүтээж/ачаалж туршаагүй (kernel header байхгүй). Shim нь GFP флаг, SMP, санах ойн дарамтыг загварчлахгүй; ENOMEM нь хиймэл тарилга.
  • tests/test_server.py нь Linux-ийн /proc/net/tcp-г ашигладаг; macOS/Windows-д ажиллахгүй байж болно.
  • make run нь 8080 портыг тогтоосон; өөр порт хэрэгтэй бол серверийг шууд ажиллуулна (8.1.4). Порт завгүй бол Python алдааны мэдээлэл (traceback) гарна.
  • UI-г зөвхөн Chromium (Brave 156)-ээр шалгасан. UI-ийн автомат шалгалт tests/ui/browser_check.py, tests/ui/interactions.py нь make test-д ороогүй, суулгасан Brave/Chromium шаарддаг (8.2.5).
  • collatz delete нь дурын зангилааг устгадаг тул дараалал Collatz-ийн дүрмээс гажиж болно (энэ нь жагсаалтын үйлдлийг үзүүлэх зорилготой).
  • Амжилтгүй команд түр аллокацийг буцаадаг тул kmalloc-ийн дугаарт (#) зай гарч болно.
  • Сервер зөвхөн локал (127.0.0.1) хэрэглээнд зориулсан, олон хэрэглэгчийн орчин биш.
